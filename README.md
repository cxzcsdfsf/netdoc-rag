# netdoc-rag · 课程实验文档检索问答

把一堆零散的实验报告做成能提问的知识库：**自己实现切分、检索、生成三层链路，零第三方依赖，纯标准库跑起来。**

不依赖任何智能体平台——不消耗积分，不怕平台关停，每一层逻辑都能讲清楚。

## 它解决什么问题

课程实验文档散在十几个目录里，几百份 txt，想知道「EIGRP 的 FD 和 AD 怎么算」「VRRP 主备怎么配」只能一份一份翻。
通用大模型又答不了：它不知道你的内部资料，问细节就编。

这个工具做三件事：**切分文档 → 按问题检索 → 只根据检索到的片段回答**，答不出来就明说。

## 跑起来

只需要 Python 3.8+，不需要 `pip install` 任何东西。

```bash
git clone https://github.com/<你的用户名>/netdoc-rag.git
cd netdoc-rag
python ask.py
```

交互模式直接输问题。单次提问：

```bash
python ask.py --ask "EIGRP 的 FD 和 AD 怎么计算"
```

换自己的文档目录：

```bash
python ask.py --docs "D:/我的实验文档"
```

`--docs` 指向的目录会被递归遍历，读所有 `.txt`。

## 接入大模型（可选）

默认只做**检索**，把最相关的片段原文列出来，这已经能用了。
想要成段回答，接一个免费模型：

1. 在 `bigmodel.cn` 注册，创建 API Key
2. 选 `glm-4-flash`（免费额度够个人用）

```bash
set ZHIPU_API_KEY=你的key
python ask.py --llm
```

或直接传参：`python ask.py --llm --key 你的key`

## 三层链路，每层都有取舍

**切分**
按空行分段，单块超过 400 字再切，块间保留 80 字重叠。
重叠是故意的——不留重叠，答案正好落在切口上就会被劈成两半，检索到哪一半都答不全。

**检索**
字符 bigram 做 token，自己实现 BM25 排序。
不用 jieba 是为了零依赖；中文不分词也能靠 bigram 拿到不错召回，代价是精度略低。
排序分两阶段：BM25 粗排 30 条保召回，再用「查询词块是否原样出现」重排取前 4 条保精度。

**生成**
top-4 片段拼进 Prompt，system 里写死三条约束：只能依据资料回答、资料没有就明说、不得编造设备参数。
回答要求带 `[资料N]` 标注——引用可核查，幻觉也就压住了。

**外加一步脏数据清洗**
从 `.doc` 解析出的文本常掺二进制乱码（`洀H渄H甄` 这类）。
用「中文字符占比 + GB2312 可编码比例」两个条件过滤，实测文本块从 2419 降到 1082，脏数据不参与检索。

## 已知问题

主动写出来，因为这些都是真实存在的边界：

1. 文档是学生实验报告，不是配置手册，很多只有需求描述没有完整命令，答案深度受限
2. bigram 对同义词不敏感，问「网关冗余」不一定命中「VRRP」
3. 没有向量检索，语义相近但用词不同的问法召回不到

## 可继续做的方向

- 换 embedding 检索，解决同义词问题
- 加网页界面，改成可视化问答
- 支持 PDF / docx 直接入库，省掉预处理
